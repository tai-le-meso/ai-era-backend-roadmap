What I learn
Laziness and the terminal operationIntermediate operations build a pipeline and do nothing. Nothing executes until a terminal operation runs. Short-circuiting terminals (findFirst, anyMatch, limit) stop early, so a map with a side effect may run zero times — which is why side effects in map are a bug.
Stateful vs stateless operationsfilter and map are stateless. sorted and distinct are stateful and must buffer — sorted on an infinite stream never terminates. This is the difference that makes some pipelines O(n) and others O(n log n) with a full materialisation.
reduce and associativityreduce requires an associative, non-interfering, stateless accumulator. A mutable accumulator in reduce is a bug that only appears in parallel. collect is the correct tool for mutable reduction.
Optional's intended scopeThe javadoc is explicit: Optional is a return type for methods that may have no result. It is not for fields, not for parameters, and not for collections — an empty collection already expresses absence.
What I do
  1. Read the java.util.stream package javadoc — it is the specification, not a tutorial.
  2. In jshell, prove laziness: a map with a println followed by findFirst on a 1000-element stream.
  3. Write down which of your work codebase's stream pipelines are stateful (contain sorted/distinct) and therefore fully materialise.
  4. Note the three places you have seen Optional used as a field or parameter.
What I conclude
  • Laziness means the pipeline's cost depends on the terminal operation, not on the number of intermediate steps.
  • Parallel-safety failures in reduce are invisible in sequential tests — the test suite passes and production is wrong.
  • Optional as a field adds allocation and serialization problems for no expressiveness gain.
What I remember & apply
Nothing runs until the terminal operation → apply: never put a side effect in map or peek and rely on it happening.
sorted/distinct are stateful and buffer the whole stream → apply: avoid them on large or unbounded sources.
reduce needs associativity; use collect for mutable accumulation → apply: audit any reduce with a StringBuilder or list.
Optional is a return type only → apply: use empty collections, not Optional<List<T>>.
