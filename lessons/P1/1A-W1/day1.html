Learn I — Language fundamentals audit & the type system

Modern Java Mastery · Phase 1 — Engineering Foundation · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
Primitives vs references, and where the boundary bitesA primitive holds the value; a reference holds an address. Autoboxing crosses that boundary silently — Integer caches -128..127 by default, so Integer.valueOf(127)==Integer.valueOf(127) is true and 128 is false. Every boxed value in a hot loop is an allocation.
== vs equals as an identity question== compares references for objects; equals compares whatever the class decided. The bug is never the operator, it is assuming a class implements equals when it does not.
The type system: subtyping, erasure, raw typesGenerics are compile-time only — List<String> and List<Integer> are the same class at runtime. Erasure means you cannot do new T[], cannot overload on List<String>/List<Integer>, and casts inserted by the compiler can throw ClassCastException far from the real mistake.
var and where inference stops helpingvar infers the static type of the initializer. It cannot be used for fields, parameters, or a bare lambda, and on a long fluent chain it hides the intermediate type from the reader — the compiler still knows, you don't.
Modern syntax you skip in day-job codeText blocks for SQL/JSON literals, enhanced instanceof patterns removing the cast line, labelled break for nested loops, and switch expressions that return a value and must be exhaustive.
What I do
  1. Open jshell and prove the Integer cache boundary yourself — print Integer.valueOf(127)==Integer.valueOf(127) then 128.
  2. Write a 20-line class using a raw List, compile with -Xlint:unchecked, and read the warning text carefully.
  3. Rewrite three if (x instanceof Foo) { Foo f = (Foo) x; ... } blocks from your work codebase as instanceof patterns.
  4. Write notes in your own words on erasure: what it removes, and one thing it makes impossible.
What I conclude
  • Boxing is not free — it is an allocation plus a cache lookup, and in a hot path it shows up as GC pressure long before it shows up as CPU.
  • Erasure is a compatibility decision from 2004, not a design ideal; most generics surprises trace back to it.
  • var is a readability tool, not a typing shortcut — use it when the initializer already names the type.
What I remember & apply
Integer cache is -128..127 (upper bound tunable via -XX:AutoBoxCacheMax) → apply: never compare boxed numerics with ==, and audit any Long id comparison in your codebase today.
Generics are erased; List<String>.class does not exist → apply: when you need runtime type info, pass a Class<T> token or a TypeReference.
switch expressions must be exhaustive → apply: use them over sealed types so the compiler catches a missing case at build time.
Text blocks preserve incidental indentation rules → apply: use them for the SQL in your integration tests instead of string concatenation.
