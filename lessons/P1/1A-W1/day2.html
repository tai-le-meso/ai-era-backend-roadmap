What I learn
Wildcards and capture? extends T is a producer you can read from; ? super T is a consumer you can write to. Capture is the compiler naming an anonymous wildcard type internally — capture errors read as capture#1 of ? extends X and mean you tried to write into a producer.
Bounded type parameters vs wildcards<T extends Comparable<T>> constrains the method's own type variable; List<? extends Number> constrains a single parameter. Use a type parameter when two positions must agree, a wildcard when only one position matters.
Package structure as an enforced boundaryA layered structure (api / application / domain / infrastructure) is only real if something enforces the direction. Package-private visibility plus a later ArchUnit rule is the enforcement; a naming convention alone is decoration.
Spring Boot project anatomy@SpringBootApplication is component scan + auto-configuration + configuration. Component scanning starts at that class's package, which is why the main class sits at the root of your package tree.
What I do
  1. Create the flagship repo: Spring Boot 4.x, Java 25, Gradle or Maven, Spotless configured to fail the build on format drift.
  2. Lay out api / application / domain / infrastructure packages and write a one-paragraph README explaining the dependency direction.
  3. Implement POST /customers end-to-end with a record request DTO and a 201 response.
  4. Add Testcontainers as a dependency and start a PostgreSQL container in one throwaway test — do not use it yet, just prove it boots.
What I conclude
  • PECS is about who reads and who writes, not about being clever with syntax.
  • A package structure that nothing enforces will erode within a quarter — plan the enforcement now, add it in Week 7.
  • Starting with Testcontainers on day one is cheaper than retrofitting it after 40 tests are written against H2.
What I remember & apply
Producer Extends, Consumer Super → apply: type your service method params Collection<? extends Event> when you only iterate them.
Component scan starts at the @SpringBootApplication package → apply: never put the main class in a leaf package.
Spotless failing the build removes format from code review → apply: configure it before the second commit, not the hundredth.
