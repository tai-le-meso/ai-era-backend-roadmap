Learn I — JIT, profiling & diagnostics

JVM Internals, Concurrency & Performance · Phase 1 — Engineering Foundation · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
Tiered compilationCode starts interpreted, gets compiled by C1 (fast, lightly optimised) once warm, then by C2 (slow, aggressively optimised) if very hot. This is why the first thousand iterations of anything are meaningless — and why a benchmark without warmup measures the interpreter.
Inlining and escape analysisC2 inlines small hot methods, which enables everything else. Escape analysis proves an object never leaves a scope, allowing scalar replacement — the allocation disappears entirely. This is why 'it allocates in a loop' is sometimes free and sometimes not.
DeoptimisationC2 speculates: assumes a branch is never taken, a type is always the same, a method is never overridden. When the assumption breaks, the frame deoptimises back to the interpreter and recompiles. A polymorphic call site that suddenly sees a second type is a classic cause.
Sampling vs instrumenting profilersSampling takes periodic stack snapshots — low overhead, statistically accurate, safe in production. Instrumenting rewrites bytecode to count — exact but distorts what it measures, especially inlining.
What I do
  1. Read the man pages for jcmd, jstack, jstat.
  2. Run the flagship under load and capture a flame graph with async-profiler.
  3. Take a thread dump mid-load with jstack and identify one blocked thread and its lock owner.
  4. Predict the top 3 hot paths before you look at the flame graph.
What I conclude
  • Warmup is not a benchmarking ritual; it is the difference between measuring the interpreter and measuring the shipped code.
  • Sampling profilers are safe in production — this is the tool you will actually reach for during an incident.
What I remember & apply
Interpreter → C1 → C2 tiering → apply: always warm up before measuring; anything else measures the wrong code.
Escape analysis can delete an allocation entirely → apply: don't hand-optimise object creation before checking whether the JIT already did.
A bimorphic call site can trigger deopt → apply: watch for it when a hot interface gains a second implementation.
jstack shows lock owners → apply: first command when threads appear stuck.
