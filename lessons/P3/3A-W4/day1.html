Learn I — Consistency models

Reliability, Consistency & Coordination · Phase 3 — Distributed Systems · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
LinearizabilityThe strongest single-object model: every operation appears to take effect at a single instant between its invocation and its response, and once a write is visible it is visible to everyone. It is what people mean by 'strong consistency', and it costs a coordination round-trip on every operation.
Sequential, causal, eventualSequential: all nodes see the same order, but that order need not match real time. Causal: operations that are causally related are seen in order by everyone; concurrent ones may differ. Eventual: replicas converge if writes stop — a liveness property with no safety guarantee at all.
Session guaranteesRead-your-writes, monotonic reads (never see time go backwards), monotonic writes (your writes apply in order), writes-follow-reads. These are per-client guarantees and are usually what users actually notice — which makes them more practical than the global models.
CAP stated correctly, PACELC as the better frameCAP: during a network partition, choose availability or consistency. It says nothing about normal operation, which is where systems spend almost all their time. PACELC extends it: if Partitioned, choose A or C; Else, choose Latency or Consistency. That second clause is the daily trade-off.
What I do
  1. Read Jepsen's consistency-models index and place PostgreSQL, Kafka and Redis on it.
  2. Write the definition of each session guarantee in your own words.
  3. For each flagship read path, name the weakest consistency you could tolerate.
  4. State the business consequence of getting each one wrong.
What I conclude
  • Session guarantees are more useful in practice than the global models because they map to what a single user experiences.
  • PACELC's 'else latency or consistency' is the trade-off you make every day; CAP's partition case is rare.
What I remember & apply
Linearizability = single instant, globally visible → apply: costs a round trip; only pay it where required.
Read-your-writes is a per-session guarantee → apply: usually the minimum acceptable for anything a user just changed.
PACELC: if Partition then A/C, Else Latency/Consistency → apply: use this framing in design docs instead of CAP.
Eventual consistency is a liveness property, not a safety one → apply: 'eventually correct' says nothing about now.
