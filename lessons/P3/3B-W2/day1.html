Learn I — Sagas: choreography

Distributed Transactions & Observability · Phase 3 — Distributed Systems · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
What a saga isA sequence of local transactions, each committing independently, with a compensating transaction for each step that can undo its effect semantically. You trade atomicity (ACID) for availability, getting ACD: atomicity is replaced by eventual completion or eventual compensation.
Compensation is not rollbackA rollback erases history as if nothing happened. A compensation is a new forward action that semantically undoes a previous one — a refund, not an un-charge. The intermediate state was real and observable, and that is the fundamental difference.
Saga isolation anomaliesBecause each step commits, other transactions can observe intermediate states. Lost updates (another transaction overwrites a saga's write), dirty reads (reading a state that will be compensated), and fuzzy reads (reading twice, seeing different states). These are real, and they need explicit countermeasures.
The countermeasuresSemantic lock: mark the record as pending so others know. Commutative updates: design operations so order does not matter. Pessimistic view: reorder steps so risky ones happen last. Re-read value: check the value has not changed before writing. Version file: record operations and reorder them. By-value: route low-risk sagas differently from high-risk ones.
What I do
  1. Read the saga pattern page and write down the difference between compensation and rollback in your own words.
  2. For the Payment → Order → Inventory → Notification flow, write each step and its compensation.
  3. Identify which steps are not compensable — a sent notification, an executed external transfer.
  4. Choose a countermeasure for each isolation anomaly you can foresee.
What I conclude
  • The intermediate states of a saga are visible to users and to other transactions; designing them is part of the work.
  • Non-compensable steps determine step ordering: they must go last, or be made provisional.
What I remember & apply
Compensation is a forward action, not a rollback → apply: design the refund, don't imagine an undo.
Sagas give ACD, not ACID → apply: say this explicitly when someone expects transactional behaviour.
Semantic lock = mark as pending → apply: the cheapest countermeasure and usually the right first one.
Non-compensable steps go last → apply: send the notification after everything else has committed.
