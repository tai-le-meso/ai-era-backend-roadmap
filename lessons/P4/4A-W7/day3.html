Build the core — Domain modelling under pressure + consolidation

What I learn
Model rotUbiquitous language decays as people join, requirements shift, and shortcuts accumulate. The symptoms: two names for one concept, one name for two concepts, and comments explaining what a class 'really' means. Periodic renaming is maintenance, not churn.
Answering the as-of questionWrite the query that answers 'what was the limit on date D as known on date K' and put it in the runbook — it is the query an auditor will ask for.
What I do
  1. Write and test the as-of query with both time dimensions.
  2. Update the context map with anything the week's work changed.
  3. Do a language audit: find one concept with two names and one name with two meanings.
  4. Commit the bitemporal model and the read model.
What I conclude
  • The as-of query is the deliverable that proves the bitemporal model works.
  • A language audit takes an hour and usually finds something worth fixing.
What I remember & apply
Put the as-of query in the runbook → apply: auditors ask for it, and building it under pressure is worse.
Language audit: two names for one concept, one name for two → apply: run it every quarter.
