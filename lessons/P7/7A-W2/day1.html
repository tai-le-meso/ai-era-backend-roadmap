Learn I — Agent anatomy: planner, executor, memory, state

AI Agents & the MCP / Tool Ecosystem · Phase 7 — Agents & AI-Native Dev · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
The loopPerceive (context and tool results) → plan (decide the next action) → act (call a tool) → observe (read the result) → repeat until a termination condition. The loop is simple; everything hard is in the termination conditions and the state.
Planning strategiesReAct interleaves reasoning and acting each step — flexible, and can wander. Plan-and-execute produces a plan up front then follows it — predictable, and brittle when reality differs from the plan. Reflection adds a self-critique step — better quality, more tokens. Each has a characteristic failure mode.
Memory typesWorking memory is the context window — bounded, and the constraint. Episodic memory is what happened in this run — must be persisted for resumability. Semantic memory is durable learned facts — usually a retrieval problem, and usually over-engineered early.
An agent run is a long-running processExactly like a saga: it has state, it can fail partway, completed steps may need compensation, and it must survive a restart. The difference is that the step list is not known in advance — which makes compensation harder, not easier.
What I do
  1. Read the agent-loop section and map it onto your Week 1 implementation.
  2. Design the agent state schema: run id, step history, tool calls, results, token spend, status.
  3. Design the termination conditions: max steps, max tokens, max cost, max wall time, loop detection.
  4. Write down how compensation differs from a saga when the step list is dynamic.
What I conclude
  • Termination conditions are the safety system; without them an agent is an unbounded liability.
  • The saga comparison is exact and useful — you already know how to persist and resume a long-running process.
What I remember & apply
Loop: perceive → plan → act → observe → repeat → apply: the termination conditions are where the engineering is.
ReAct wanders; plan-and-execute is brittle; reflection costs tokens → apply: pick per task, expect the failure mode.
An agent run is a saga with a dynamic step list → apply: reuse 3B's persistence and recovery patterns.
Persist episodic memory → apply: it is what makes a run resumable after a crash.
