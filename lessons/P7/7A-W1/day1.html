Learn I — Agents vs workflows: the decision

AI Agents & the MCP / Tool Ecosystem · Phase 7 — Agents & AI-Native Dev · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
The distinction that mattersA workflow has predetermined control flow with LLM calls at fixed points — you decide the steps. An agent decides its own control flow, choosing which tools to call and when to stop. Everything else in the agent conversation is detail; this is the decision.
The spectrum between themPrompt chaining (fixed sequence), routing (classify then dispatch), parallelisation (fan out and aggregate), orchestrator-worker (a model decomposes into subtasks), evaluator-optimiser (generate then critique in a loop), and finally autonomous agents. Most problems are solved best somewhere in the middle.
What autonomy costsUnpredictable token spend, unpredictable latency, unbounded failure modes, and behaviour that is hard to test because the same input may take different paths. These are not objections to agents; they are the price, and the price must be justified.
When autonomy earns its costWhen the task space is genuinely open-ended, the number of steps is unknown in advance, and the environment provides feedback the model can act on. Reconciliation-break investigation qualifies; generating a monthly report does not.
What I do
  1. Read the Anthropic agents article carefully — it is short and unusually clear.
  2. Pick one flagship operations task: 'investigate this reconciliation break'.
  3. Design the deterministic workflow version: fixed steps, LLM calls at defined points.
  4. Design the agent version: tools, loop, termination conditions.
What I conclude
  • The workflow/agent choice is the architecture decision; everything else follows from it.
  • Most tasks that feel agent-shaped are actually a router plus three fixed steps.
  • Autonomy's cost is paid in predictability, which is exactly what production systems need.
What I remember & apply
Workflow = you decide control flow; agent = the model decides → apply: state which you are building, explicitly.
The middle of the spectrum solves most problems → apply: try routing or orchestrator-worker before full autonomy.
Autonomy costs predictability of cost, latency and behaviour → apply: justify it against those three specifically.
Agents fit open-ended tasks with unknown step counts and environmental feedback → apply: check all three before choosing.
