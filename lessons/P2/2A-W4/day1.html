Learn I — Indexes & the query planner

PostgreSQL Deep Dive · Phase 2 — Data & Messaging · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
B-tree structure and column orderA multicolumn B-tree is sorted by the first column, then the second within it. An index on (a,b) serves WHERE a=?, WHERE a=? AND b=?, and ORDER BY a,b — but not WHERE b=? alone. Column order is the single most consequential index decision.
Index-only scans and the visibility mapIf every column the query needs is in the index, PostgreSQL can skip the heap — but only if the page is marked all-visible in the visibility map, which VACUUM maintains. A table that is not vacuumed loses index-only scans silently.
Beyond B-treeGIN for containment (jsonb, arrays, full-text). GiST for geometric and range overlap. BRIN for naturally-ordered huge tables (append-only time series) — tiny index, only useful when physical order correlates with value. Hash only for equality, and rarely worth it.
Partial and expression indexesCREATE INDEX ... WHERE status = 'PENDING' indexes only the rows you query, which for a small active subset of a huge table is dramatically smaller and faster. An expression index on lower(email) is required for WHERE lower(email) = ? to use an index at all.
What I do
  1. Read indexes.html fully — it is short and dense.
  2. For each of your five slowest queries, write down which index you predict will help and why.
  3. Check whether any query is doing a sequential scan because of a function on the column.
  4. Look for a query that would benefit from a partial index.
What I conclude
  • Column order determines what an index can serve; a wrong order makes it dead weight that still costs on every write.
  • Every index is a write tax — inserts and updates maintain them all.
What I remember & apply
Multicolumn index (a,b) serves a and a,b but not b alone → apply: order columns by equality-first, then range.
Index-only scans need the visibility map, maintained by VACUUM → apply: an under-vacuumed table loses them silently.
A function on a column disables a plain index → apply: create an expression index or rewrite the predicate.
Partial indexes shrink hot subsets massively → apply: index WHERE status='PENDING' for queue tables.
