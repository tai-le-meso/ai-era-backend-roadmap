Learn I — Grounding, citation & the full RAG architecture

LLM Fundamentals & RAG · Phase 6 — AI Application Engineering · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
Context constructionOrder retrieved chunks by relevance, deduplicate near-identical ones, and budget tokens explicitly: system prompt + history + retrieved context + reserved output space must fit. Decide in advance what gets dropped first when the budget is exceeded — usually the oldest history, then the lowest-ranked chunks.
Grounding and citationRequire the model to cite the source for each claim, and then verify that the cited chunk actually supports it. An unverified citation is decoration — models will cite a real source for a claim it does not make.
Refusal when context is insufficientThe most valuable behaviour in a regulated domain. The prompt must explicitly permit and instruct refusal, the eval set must contain unanswerable questions, and the refusal rate must be monitored — too low means over-confidence, too high means uselessness.
Access control in retrievalNever retrieve documents the user cannot see. Filtering after retrieval means the content was in the pipeline, possibly in logs and traces. Access scoping must be a pre-filter on the query, ideally enforced structurally with row-level security.
What I do
  1. Implement context construction with an explicit token budget and documented drop order.
  2. Require citations in the output schema.
  3. Implement a verification step checking each citation supports its claim.
  4. Implement access-scoped retrieval as a pre-filter, enforced structurally.
What I conclude
  • An unverified citation gives false confidence — it looks like grounding without being it.
  • Retrieve-then-filter is a data-leak pattern: the content entered your pipeline and your logs.
  • Refusal is a feature, and its rate is a metric.
What I remember & apply
Budget tokens across system + history + context + output → apply: define the drop order before you need it.
Verify citations actually support claims → apply: models cite real sources for claims they do not make.
Access scope must be a pre-filter → apply: post-filtering leaks into logs and traces.
Monitor refusal rate in both directions → apply: too low is over-confidence, too high is uselessness.
