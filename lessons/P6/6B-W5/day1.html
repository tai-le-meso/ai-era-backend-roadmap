What I learn
LLM-specific telemetryBeyond RED: input and output token counts, cost, TTFT, cache hit rate, guardrail trigger rate by type, refusal rate, tool-call success rate, escalation rate — broken down by model, feature and tenant. The GenAI semantic conventions give you standard attribute names so the data is portable.
Tracing the AI call chainOne trace covering retrieval spans, rerank, guardrail checks, the model call, and any tool calls. Without this you cannot tell whether slowness is retrieval, guardrails or the provider. This extends the 3B trace, so the AI path appears inside your existing request traces.
Sampling prompts and responsesStoring full prompts and responses is invaluable for debugging and building eval sets, and it is a privacy exposure — they contain user data and possibly PII that guardrails redacted before the provider but not before your logs. Sample, redact, and set retention deliberately.
Drift detectionProviders update models. A prompt that worked can degrade with no change on your side. Canary evals — a fixed question set run on a schedule against production configuration — are how you find out before your users do.
What I do
  1. Instrument the AI path with GenAI semantic-convention attributes.
  2. Extend the existing traces so retrieval, guardrails, model and tools appear as spans in one trace.
  3. Implement PII-safe sampling of prompts and responses with a retention policy.
  4. Build the AI observability dashboard: cost, latency, quality, guardrail rates.
What I conclude
  • Standard attribute names make your AI telemetry portable and comparable — worth adopting from the start.
  • Prompt/response logs are user data; they need the same classification as anything else.
What I remember & apply
Use GenAI semantic conventions for attribute names → apply: portable telemetry, comparable across tools.
One trace: retrieval → rerank → guardrails → model → tools → apply: otherwise you cannot localise latency.
Sample prompts/responses with redaction and retention → apply: they are user data, not debug output.
Providers update models silently → apply: canary evals are the only detection.
