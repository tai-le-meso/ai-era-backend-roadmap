Learn I — When NOT to use an LLM + consolidation

LLM Fundamentals & RAG · Phase 6 — AI Application Engineering · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
The decision frameworkIs the task deterministic? Then write code. Is it a lookup? Then it is a query. Is it a fixed set of rules? Then it is a rule engine. Is it genuinely open-ended language understanding with tolerance for error? That is where an LLM earns its place.
Cost per outcome, not per callAn LLM call costing a fraction of a cent looks cheap until you compare it with a SQL query costing effectively nothing, at ten thousand times the volume, with deterministic results and no evaluation harness to maintain.
Where non-determinism is disqualifyingCredit decisions, sanctions blocking, limit enforcement, and anything requiring identical outcomes for identical inputs or a legally explainable rationale. In these cases accuracy is irrelevant — the decision procedure itself must be deterministic and explainable.
Fine-tuning vs RAG vs prompting vs codePrompting for behaviour shaping. RAG for knowledge the model lacks. Fine-tuning for consistent format or style at scale, rarely for facts. Plain code whenever the task is actually deterministic — which it is more often than the current enthusiasm suggests.
What I do
  1. List every flagship feature currently using an LLM.
  2. For each, ask the four framework questions and record the answer.
  3. Identify the three most likely to be better served without an LLM.
  4. Note any place where a non-deterministic decision would be non-compliant.
What I conclude
  • Most 'AI features' in a banking system are classification or extraction problems with deterministic alternatives.
  • Compliance can rule out an LLM regardless of measured accuracy — the argument is about procedure, not performance.
What I remember & apply
Deterministic task → code; lookup → query; fixed rules → rule engine → apply: exhaust these before reaching for an LLM.
Compare cost per outcome, not per call → apply: include the eval harness and monitoring in the LLM's cost.
Non-determinism is disqualifying for regulated decisions → apply: credit, sanctions, limits are code, not prompts.
Fine-tune for format, RAG for knowledge, prompt for behaviour → apply: fine-tuning rarely fixes factual gaps.
