Learn I — The capstone: design from a blank page

Architecture Decision-Making, Communication & Capstone · Phase 8 — Solution Architecture · ~4.5h
Day 1 — Learn IDay 2Day 3Day 4↑ Week overview
What I learn
This week is application, not new materialEverything you need you already have: the design framework from 4B, the domain modelling from 4A, the reliability reasoning from 3A, the cost model from 8A, and the communication practice from 8B-W2. The exercise is doing it all, solo, on a problem you have not seen.
Choosing the problemGenuinely ambiguous, ideally real. 'Design the payment infrastructure for a marketplace expanding into three new countries' works: it has unclear requirements, regulatory constraints, real scale questions, and no obviously right answer.
Timeboxing the phasesRequirements 2h, domain model 3h, architecture options 3h, decision and ADR 2h, capacity and cost 2h, failure analysis 2h, implementation plan 2h, risk register 1h. Timeboxing prevents the comfortable phases from consuming the uncomfortable ones.
Logging your AI usage as you goEvery point where you accept, reject or modify AI input, with the reason. This log is the artifact that demonstrates judgment, and it must be written during the work rather than reconstructed afterwards.
What I do
  1. Choose the ambiguous problem and write the initial brief.
  2. Run requirements elicitation: functional, non-functional, out of scope, and the questions you would ask stakeholders.
  3. Build the domain model: subdomains, bounded contexts, key aggregates.
  4. Start the AI-decision log now, not at the end.
What I conclude
  • Doing the full pipeline solo, timeboxed, is the closest thing to the real job you can practise.
  • The AI-decision log written during the work is credible; reconstructed afterwards it is a narrative.
What I remember & apply
Timebox each phase → apply: prevents the comfortable phases eating the uncomfortable ones.
Choose a genuinely ambiguous problem → apply: a well-specified problem tests the wrong skill.
Log AI decisions as you go → apply: accept/reject/modify with reasons, written live.
You already have every tool → apply: this week is integration, not learning.
