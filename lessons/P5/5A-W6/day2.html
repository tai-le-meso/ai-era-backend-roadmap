What I learn
External statements in practiceBanks deliver camt.053 end-of-day statements (ISO 20022) or legacy MT940/CSV; schemes deliver settlement files. Each line has booking/value dates, amount, and semi-structured references. ACH returns arrive as separate return entries (R-codes) days later — a statement is never 'final' the day it arrives, which is itself a timing-break source.
Break lifecycle: investigate, age, resolveA break is a case: detected → investigating → resolved (matched late / adjusted / written off) with an owner and an age. Ageing buckets (1d/3d/7d/30d) with escalating alerts stop breaks rotting quietly. Resolution often posts through a suspense account: unmatched inbound funds sit in suspense, and clearing suspense is a tracked workflow with a target of zero.
Automation boundaryAuto-resolve only what is provably safe (exact matches, timing breaks inside the window). Everything else goes to a human queue with suggested matches ranked by confidence. Auto-writing-off amount mismatches is how fraud hides — write-offs need maker-checker (W7) and a threshold policy.
What I do
  1. Download the camt.053 message definition from iso20022.org and map its statement-entry fields to your ingest model.
  2. Skim the Nacha dev guide's file structure and returns sections; note how a return references its original entry.
  3. Design the recon schema: statement_file, statement_line, match (line↔entries, confidence, strategy), break_case (category, age, owner, resolution).
  4. Define matching rules as ordered strategies (exact → reference-fuzzy → amount+date-window → one-to-many grouping) with confidence scores.
What I conclude
  • Design ingest against the standard (camt.053) and adapt legacy formats into it, not vice versa.
  • A break is a workflow object with an owner and an age, not a log line.
  • The suspense account is the recon module's buffer — its balance and age are the module's health metrics.
What I remember & apply
camt.053 = end-of-day bank statement; camt.052 = intraday report → apply: ingest port naming and 5B-W1 message literacy.
ACH/SEPA returns arrive days later and re-open 'done' payments → apply: state machine must allow settled→returned in 5B-W2.
Auto-resolve only provably-safe matches; write-offs require maker-checker + threshold → apply: resolution API rules on day 3.
Ordered strategy chain with confidence scores beats one clever matcher → apply: implementation structure tomorrow.
