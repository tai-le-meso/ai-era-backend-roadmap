How it runs — two parallel lanes

Backend lane · 22.5h/week

Phases 1–5 and 8, in sequence. Java and the JVM, PostgreSQL, Redis, Kafka, reliability and observability, DDD and architecture, the banking domain, then architecture at scale. Twelve sub-roadmaps, 1,404 hours.

AI lane · 7.5h/week

Phases 6–7, interleaved from week one so AI is never learned last. Each block is scheduled after its backend prerequisite — vector search alongside PostgreSQL, the AI gateway alongside circuit breakers, agents after sagas. Four sub-roadmaps, 468 hours.

The content ratio is exactly 3:1, so both lanes finish together at week 62.4 — about month 14.4. Nothing is cut.

What a daily lesson contains

SectionWhat it gives you
What I learn3–6 specific technical points with real detail — not summaries. Why HashMap treeifies a bin at 8 entries, what acks=all with min.insync.replicas=1 actually guarantees, how LLM-judge verbosity bias skews evaluation.
What I do3–5 concrete actions for the session — read this spec section, reproduce this failure, measure this, write this test.
What I concludeThe trade-offs and judgment calls the day's work should leave you with.
What I remember & applyFlashcard-style facts, each ending in an → apply: pointer telling you where to use it in real work.
Sources4–6 official references per week, badged verified where the URL was confirmed reachable when the pack was built.

Using it

  • Open the tracker, set a start date, and expand the sub-roadmap you are on. Every week row links to its four daily lessons.
  • Tick blocks and exit-checklist items as you go. Progress lives in the browser tab only — use Export to save a JSON snapshot and Import to restore it.
  • Read the parallel plan for the schedule and the weekly rhythm, and the overview for the original 24-month framing.
  • Every sub-roadmap has an exit checklist. Do not advance with more than two items failing.
Built around one flagship project — a mini core-banking / payment platform that evolves from v0 to v8.final across the whole roadmap.
